## image object quantity metric (IOQM)

This repo contains code for:

1. building a dataset of image prompts with quantities of objects for evaluation
   - the objects are a set of 79/80 objects used in the COCO dataset. https://docs.ultralytics.com/datasets/detect/coco/#dataset-yaml

   - a mini version of the dataset containing ~16k images from a random subset of 10 COCO object classes lives here: https://huggingface.co/datasets/semaj83/ioqm
2. running various generative models through huggingface diffusers/transformers libraries
3. evaluating images generated using the original object detection model developed by facebook for the dataset: `facebook/detr-resnet-50`

## v3 harness (2026 revival — see `docs/plan.md`)

The plan and literature review are in `docs/`. Phase 0 code:

| Path | What it is |
|---|---|
| `ioqm/classes.py` | Canonical COCO-80 table: hand-written plurals, aliases, and a flag for classes whose counting unit is ambiguous. Replaces prefix matching |
| `ioqm/prompts.py` | `PromptSpec` (ground truth stored as data, not in filenames), rendering, legacy prompt parser, nested v3 builder, stratified evaluation subset. Splits: `train`, `test_id`, `test_single`, `test_ood_pair` (a class pair never seen together in any training prompt), `test_ood_triple` (a new triple made of familiar pairs), `test_ood_count` |
| `ioqm/metrics.py` | Fixed metrics (primary: `prompt_exact`) and cluster/paired bootstrap CIs |
| `ioqm/generate.py` | Model registry and generation that resumes after a disconnect (`manifest.jsonl` + `run_config.json`) |
| `ioqm/detect.py` | Stores raw detections at a low confidence floor, then counts at any global or per-class threshold |
| `scripts/` | `build_prompts_v3.py`, `generate.py`, `benchmark_speed.py`, `import_legacy_run.py`, `score.py` |

`run_eval.py`'s `hard_ioqm` / `soft_ioqm` are kept **unchanged** so the 2023 numbers can be reproduced. Their bugs are documented in the docstring.

```bash
python -m pytest tests -q                 # no GPU needed
python scripts/build_prompts_v3.py        # -> prompts/v3/{all,train,eval_subset}.jsonl
```

### Colab notebooks

Notebook cells only call `scripts/`; all logic lives in `ioqm/` and is unit-tested. The notebooks are generated by `tools/make_notebooks.py` and `tools/make_phase0_notebook.py`, so edit those, not the `.ipynb` files.

| Notebook | Runtime | What it runs |
|---|---|---|
| [`notebooks/phase0_colab.ipynb`](notebooks/phase0_colab.ipynb) | A100 | Model timing, best-of-16 pilot, z_image_turbo eval run, 2023 re-score, Phase 1 (counters vs 2023 human labels, labelling queue, VLM counter) |
| [`notebooks/overopt_colab.ipynb`](notebooks/overopt_colab.ipynb) | A100 | Over-optimization study: best-of-k up to 64 against each proxy counter, scored by an independent gold judge; human check of real picks; mechanism analyses |
| [`notebooks/label_colab.ipynb`](notebooks/label_colab.ipynb) | CPU | Blind click-to-count labeller for either labelling queue |

To label on a Mac instead of Colab, with Google Drive for desktop set to *Stream files*: `pip install gradio`, then `python scripts/label.py` (round 1) or `python scripts/label.py --round picks` (round 2). It opens in your browser and downloads only the queued images. Keys: 1/2/3 class, z undo, a ambiguous, Enter submit.

Open one from GitHub in Colab, e.g. `https://colab.research.google.com/github/semajyllek/ioqm/blob/phase0-harness/notebooks/overopt_colab.ipynb`, and use Run all. Every step resumes after a disconnect; data lives on Drive under `MyDrive/ioqm_data/`.

### Code layout

| Module | Role |
|---|---|
| `ioqm/classes.py`, `ioqm/prompts.py` | COCO class names and the v3 prompt set |
| `ioqm/generate.py` | Model registry and resumable generation |
| `ioqm/counters.py`, `ioqm/detect.py` | Counters (YOLOv8x, Mask2Former, DETR, Qwen3-VL) and stored detections |
| `ioqm/metrics.py` | Per-image metrics and cluster-bootstrap CIs |
| `ioqm/best_of_n.py`, `ioqm/overopt.py` | Best-of-N selection; unbiased best-of-k over-optimization curves |
| `ioqm/labels.py`, `ioqm/sampling.py`, `ioqm/agreement.py`, `ioqm/labeler.py` | Human labels, labelling queues, counter-vs-human agreement, Gradio labeller |
| `ioqm/analysis.py`, `ioqm/cooccurrence.py` | Mechanism analyses and COCO co-occurrence |
